# 03 — Method and Math

## Method summary

The current implemented method is:

> Custom PyTorch Double DQN for target-revealing Webots navigation, with a hidden-target search regime before reveal and a learned target-approach regime after reveal.

The planned continual-learning method adds:

> OPR-inspired Selective Search Episode Replay (SSER) and a DQN-compatible online EWC approximation inspired by KGCRL.

This is an inspired-by adaptation, not an exact implementation of OPR or KGCRL.

## Q-network

The current code uses a compact MLP:

$$
o_t
\rightarrow
\mathrm{FC}(256)
\rightarrow
\mathrm{ReLU}
\rightarrow
\mathrm{FC}(256)
\rightarrow
\mathrm{ReLU}
\rightarrow
Q(o_t,\cdot)
$$

with:

$$
\dim(o_t)=19,
\qquad
|\mathcal{A}|=3.
$$

## Transition format

The current replay transition is:

$$
(s_t,a_t,s_{t+1},r_t)
$$

represented in code as:

```python
Transition = namedtuple('Transition', ('state', 'action', 'next_state', 'reward'))
```

A terminal transition is represented by:

```python
next_state = None
```

The current implementation does not store macro-action duration in the transition.

## Double DQN target

The current code uses a one-step Double DQN target.

For terminal transitions:

$$
y_t=r_t.
$$

For non-terminal transitions:

$$
y_t=r_t+\gamma Q_{target}\left(s_{t+1},
\arg\max_{a'} Q_{online}(s_{t+1},a')
\right).
$$

The discount is:

$$
\gamma=0.99.
$$

The loss is Huber/Smooth L1 loss:

$$
L_{DQN}=\mathrm{SmoothL1}(Q_{online}(s_t,a_t),y_t).
$$

## Target network update

The target network is softly updated after optimization:

$$
\theta_{target}
\leftarrow
\tau\theta_{online}+(1-\tau)\theta_{target}
$$

with:

$$
\tau=0.005.
$$

## Exploration schedule

The current epsilon schedule is:

$$
\epsilon_t=\epsilon_{end}+(\epsilon_{start}-\epsilon_{end})\exp(-t/\epsilon_{decay})
$$

with:

| Parameter | Value |
|---|---:|
| $\epsilon_{start}$ | `0.9` |
| $\epsilon_{end}$ | `0.01` |
| $\epsilon_{decay}$ | `2500` |

## Current replay buffer

The current replay buffer stores DQN transitions generated by the active policy. Since the current code continues DQN control after reveal, the replay buffer may contain both pre-reveal search transitions and post-reveal target-approach transitions.

If an experiment needs search-only replay analysis, pre-reveal and post-reveal transitions should be explicitly tagged and filtered.

## SSER: OPR-inspired Selective Search Episode Replay

SSER is the project name for the adapted OPR-style replay mechanism.

SSER means:

> **Selective Search Episode Replay** stores high-quality previous-scene episodes and reuses them during later-scene DQN training.

SSER is inspired by OPR because both methods preserve high-quality past navigation experience to reduce forgetting. SSER differs from original OPR because it does not use A3C, ACER, Retrace, stored policy probabilities, or stored value outputs. It is a DQN-compatible mixed-replay mechanism.

## SSER episode quality

After each scene, store top-K high-quality episodes.

Episode quality should prioritize:

1. target revealed,
2. target reached,
3. high coverage,
4. low collisions,
5. fewer decision steps,
6. higher total reward.

Example planned episode record:

```python
episode = {
    "scene_id": scene_id,
    "transitions": [...],
    "metrics": {
        "revealed": bool,
        "reached": bool,
        "unique_cells_covered": int,
        "collisions": int,
        "decision_steps": int,
        "reward": float,
    },
}
```

## SSER mixed replay

During later scenes, sample minibatches using:

$$
80\%\text{ current replay}+20\%\text{ old SSER replay}.
$$

For the current batch size of `64`, this corresponds approximately to:

- `51` current-scene transitions,
- `13` old selective-replay transitions.

When training on scene 3, old SSER replay should include selected episodes from both scenes 1 and 2. The old replay should be sampled in a way that avoids drowning out the earliest scene.

## Online EWC approximation

Use online EWC, not multi-anchor EWC.

The total loss for an EWC-enabled variant is:

$$
L = L_{DQN}+L_{EWC}
$$

with:

$$
L_{EWC}=\frac{\lambda}{2}\sum_i F_i^{acc}(\theta_i-\theta_i^*)^2.
$$

where:

- $\theta^*$: latest saved parameter anchor after a scene,
- $F_i^{acc}$: accumulated diagonal parameter-importance estimate,
- $\lambda$: EWC strength.

After each scene:

$$
F_i^{acc}\leftarrow \rho F_i^{acc}+F_i^{new}
$$

$$
\theta^*\leftarrow \theta^{*(k)}.
$$

## Parameter importance estimate

Use squared gradients of the DQN loss:

$$
F_i^{new}\approx
\mathbb{E}\left[\left(\frac{\partial L_{DQN}}{\partial\theta_i}\right)^2\right].
$$

Call this a:

> DQN-compatible diagonal EWC approximation.

Do not call it the exact KGCRL Fisher estimate.

## Training variants

Implement and compare variants in this order:

1. `finetune`: Double DQN only
2. `replay`: Double DQN + SSER
3. `ewc`: Double DQN + online EWC
4. `replay_ewc`: Double DQN + SSER + online EWC

The final comparison should include at least `finetune` and `replay`. Add `ewc` and `replay_ewc` after the base system is stable.
