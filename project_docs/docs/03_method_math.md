# 03 - Method and Math

## Method summary

The current implemented method is:

> Custom PyTorch Double DQN for target-revealing Webots navigation, with a hidden-target search regime before reveal and a learned target-approach regime after reveal.

The current code also contains optional continual-learning variants:

> Double DQN + OPR-inspired Selective Search Episode Replay (SSER), Double DQN + EWC-style regularization, and Double DQN + SSER + EWC.

This is an inspired-by adaptation, not an exact implementation of OPR or KGCRL. In particular, the current EWC implementation uses a Q-output-sensitivity approximation, not the documented future TD-loss-gradient importance estimate.

## Q-network

The current code uses a compact MLP:

$$
o_t
\rightarrow
\mathrm{FC}(256)
\rightarrow
\mathrm{ReLU}
\rightarrow
\mathrm{FC}(256)
\rightarrow
\mathrm{ReLU}
\rightarrow
Q(o_t,\cdot)
$$

with:

$$
\dim(o_t)=19,
\qquad
|\mathcal{A}|=3.
$$

The action-index order is:

| Action index | Code action |
|---:|---|
| `0` | `forward` |
| `1` | `rotate_right` / `right` |
| `2` | `rotate_left` / `left` |

## Transition format

The replay transition is:

$$
(s_t,a_t,s_{t+1},r_t)
$$

represented in code as:

```python
Transition = namedtuple('Transition', ('state', 'action', 'next_state', 'reward'))
```

A terminal transition is represented by:

```python
next_state = None
```

The current transition does not store macro-action duration, scene id, reveal/search phase, or done flags. Phase is inferred indirectly from the observation and reward path.

## Double DQN target

The current code uses a one-step Double DQN target.

For terminal transitions:

$$
y_t=r_t.
$$

For non-terminal transitions:

$$
y_t=r_t+
\gamma
Q_{target}
\left(
    s_{t+1},
    \arg\max_{a'} Q_{online}(s_{t+1},a')
\right).
$$

The discount is:

$$
\gamma=0.99.
$$

The predicted value for each sampled transition is:

$$
Q_{online}(s_t,a_t).
$$

The DQN loss is Huber/Smooth L1 loss:

$$
L_{DQN}
=
\mathrm{SmoothL1}
\left(
Q_{online}(s_t,a_t), y_t
\right).
$$

## Optimization defaults

Current defaults in `utils/rl_specific/dqn_manager.py`:

| Hyperparameter | Value |
|---|---:|
| batch size | `64` |
| replay capacity | `10000` |
| replay warmup | `500` transitions |
| discount `gamma` | `0.99` |
| optimizer | AdamW |
| learning rate | `3e-4` |
| AMSGrad | enabled |
| gradient clipping | value clip at `100` |

Optimization starts only after the current replay buffer contains at least `500` transitions. During evaluation runs, the policy network is not optimized.

## Target network update

The target network is softly updated after each optimization step:

$$
\theta_{target}
\leftarrow
\tau\theta_{online}+(1-\tau)\theta_{target}
$$

with:

$$
\tau=0.005.
$$

## Exploration schedule

Training uses epsilon-greedy exploration:

$$
\epsilon_t=
\epsilon_{end}+(
\epsilon_{start}-\epsilon_{end})
\exp(-t/\epsilon_{decay})
$$

with:

| Parameter | Value |
|---|---:|
| $\epsilon_{start}$ | `0.9` |
| $\epsilon_{end}$ | `0.01` |
| $\epsilon_{decay}$ | `2500` |

Evaluation uses greedy action selection from the policy network.

## Current replay buffer

The current replay buffer stores DQN transitions generated by the active policy. Since DQN control continues after reveal, the buffer may contain both pre-reveal search transitions and post-reveal target-approach transitions.

If an experiment needs search-only or approach-only replay analysis, transitions should be tagged explicitly in a future refactor.

## SSER: implemented behavior

SSER means:

> **Selective Search Episode Replay** stores selected previous-scene episodes and reuses their transitions during later-scene DQN training.

Current implemented constants:

| Quantity | Value |
|---|---:|
| top-K episodes per stored scene | `K = 10` |
| total batch size | `64` |
| old SSER replay fraction | `0.25` |
| old transitions per batch | `16` |
| current transitions per batch | `48` |

During a replay-enabled training update:

$$
B = B_{current} \cup B_{old},
\qquad
|B_{current}|=48,
\qquad
|B_{old}|=16.
$$

The old replay batch is sampled as follows:

- If only scene 0 memory is available, sample all `16` old transitions from scene 0.
- If scene 0 and scene 1 memories are available, sample `8` old transitions from scene 0 and `8` from scene 1.
- The combined batch is shuffled before the Double DQN update.

The selected episodes are saved in files named:

| Training stage | Saved SSER file |
|---|---|
| after scene 0 collection | `selective-replay-buffer-0.pt` |
| after scene 1 collection | `selective-replay-buffer-0-1.pt` |

## SSER episode selection

The code stores a top-K heap of episode transition lists. The current episode score is:

$$
\mathrm{score}
=
\frac{\mathrm{unique\_cells\_covered}-\mathrm{collisions}}
{\mathrm{decision\_steps}}.
$$

Current implementation limitation:

- Episodes are added to SSER only when `reached=True`.
- The project metric still treats `revealed=True` as the primary continual-learning success condition.
- This means reveal-only episodes are currently not preserved in SSER, even though they may be valuable for the main target-reveal metric.
- If not enough old SSER transitions exist, current sampling can fail because it uses `random.sample` without replacement.

This differs from the intended ranking described for future refinement, where reveal success should be prioritized before reach success.

## EWC-style regularization: implemented behavior

EWC-enabled variants add a regularization term to the DQN optimization loss:

$$
L
=
L_{DQN}
+
\lambda L_{EWC}
$$

with:

$$
\lambda=10.0.
$$

The EWC object computes:

$$
L_{EWC}
=
\frac{1}{2}
\sum_i
F_i^{acc}
(\theta_i^* - \theta_i)^2.
$$

where:

- $\theta_i^*$ is the saved parameter anchor from the previous EWC state,
- $\theta_i$ is the current online Q-network parameter,
- $F_i^{acc}$ is the accumulated diagonal importance estimate.

EWC state files contain:

```python
{
    "mean_params": ...,
    "kernel_diag": ...,
}
```

The saved EWC filenames are:

| Training stage | Saved EWC file |
|---|---|
| after scene 0 training | `ewc_state-0.pt` |
| after scene 1 training | `ewc_state-0-1.pt` |

## EWC importance approximation

The intended project method is a DQN-compatible squared-gradient importance estimate from the TD loss:

$$
F_i^{new}
\approx
\mathbb{E}
\left[
\left(
\frac{\partial L_{DQN}}{\partial \theta_i}
\right)^2
\right].
$$

The current code does not compute this exact quantity. It stores a reservoir of transitions, extracts only their states, and computes a diagonal Jacobian-based importance estimate from:

$$
f_\theta(s)=\max_a Q_\theta(s,a).
$$

So the current implemented importance is better described as:

$$
F_i^{new}
\approx
\mathbb{E}_{s}
\left[
\left(
\frac{\partial \max_a Q_\theta(s,a)}{\partial \theta_i}
\right)^2
\right].
$$

When an existing EWC state is loaded, the code updates the diagonal importance estimate with:

$$
F^{acc}
\leftarrow
\rho F^{acc}+F^{new},
\qquad
\rho=0.9.
$$

The parameter anchor is then replaced by the current network snapshot embedded in the newly created EWC object.

Use this wording in reports unless the implementation is changed:

> The current EWC variant is an EWC-style Q-network regularizer using a Q-output-sensitivity diagonal importance approximation. It is inspired by KGCRL but is not KGCRL's exact Fisher estimate and is not yet the intended TD-loss-gradient approximation.

## Training variants

The code supports these policy labels:

| Policy label | Meaning |
|---|---|
| `dqn` | Double DQN fine-tuning baseline |
| `dqn_replay` | Double DQN with SSER mixed replay |
| `dqn_ewc` | Double DQN with EWC-style regularization |
| `dqn_replay_ewc` | Double DQN with both SSER and EWC |

The minimum comparison should include `dqn` and `dqn_replay`. Add `dqn_ewc` and `dqn_replay_ewc` when the base pipeline and saved CRL artifacts are stable.
